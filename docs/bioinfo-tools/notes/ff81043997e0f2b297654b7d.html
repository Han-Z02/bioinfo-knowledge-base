二、C4 单细胞测序平台

1. C4 单细胞测序平台介绍

C4 平台是由华大智造自主研发的一站式单细胞测序数据分析平台，C系列平台基于液滴微流控策略，可以实现高效细胞捕获，完成高效的mRNA反转录和扩增后，结合华大DNBSEQ™高通量测序平台和Dr.Tom单细胞全交互式数据挖掘交付系统，进行高性价比单细胞转录组文库测序和数据分析挖掘，可广泛应用于研究免疫细胞、肿瘤微环境、神经系统发育及胚胎发育和干细胞分化等。

2. 测序原理#

C4 单细胞测序平台基于微流控液滴技术，但是与传统的微流控液滴技术一个cell只与一个磁珠匹配不同，C4 平台会使用一大一小两个磁珠和捕获单个细胞进行配对，不同磁珠承担不同功能：

  • 大磁珠： 携带细胞条形码（Cell Barcode）和唯一分子标识符（UMI），用于标记每个细胞的转录本来源及去重。
  • 小磁珠：用于标记大磁珠（或者说用于标记液滴），不同的液滴会带有不同的小磁珠标记（Index）,同一个液滴内的所有大磁珠都带有相同的Index标记，数据分析时，可以通过大磁珠上所携带的Index信息将同一液滴内的所有大磁珠数据进行归类，从而实现对单个细胞的转录组数据进行准确归属。

  理想情况下微流控液滴技术希望1个液滴内含有1个磁珠1个细胞，实际情况(能产生数据的液滴)中情况可能是1个磁珠1个细胞;1个磁珠多个细胞;多个磁珠1个细胞;多个磁珠多个细胞，而C4平台通过使用两种不同大小的磁珠，可以有效区分这些情况，从而实现对单细胞的高效捕获和准确归属。

三、上游定量

1. DNBseq技术

DNBseq（DNA Nanoball Sequencing） 是华大基因自主研发的高通量测序技术，核心基于 DNA纳米球（DNA Nanoball，DNB）和高密度测序芯片。与传统NGS技术（如Illumina的桥式PCR扩增）不同，DNBseq避免了PCR扩增导致的重复误差，通过线性扩增生成单链DNA纳米球，结合联合探针锚定聚合（cPAS）技术进行测序。

  DNBseq测序文库构建分为常规建库和DNB制备两大阶段：

常规建库 （与传统NGS相似）

片段化：将DNA打断至200-500bp。 末端修复 & 加接头：修复片段末端，添加与测序芯片匹配的接头序列。 纯化：选择目标片段大小。

DNB制备 （关键技术）

  • 环化：将双链DNA连接成环状单链（ssDNA circle）。
  • 滚环扩增（RCA）：以环状DNA为模板，生成串联重复的线性单链结构。
  • DNB生成：通过机械或化学断裂，形成包含多拷贝重复序列的纳米球（直径~300nm）。
  • DNB芯片加载：将DNA纳米球固定到高密度芯片上，形成规则阵列。

优势 ：因无需PCR扩增，避免了GC偏好性和重复序列错误，显著提高数据均一性。

因此我们需要采用 DNBC4tools 进行上游的定量测序，用于分析高通量 DNBelab C 系列 TM 单细胞数据集的开源且灵活的流程。

3. DNBC4tools 使用示例#

3.1 下载物种参考基因组文件#

下载参考基因组和注释文件，根据自己的物种按需选择：

  • 基因组文件：基因组文件应以 FASTA 格式提供，包含特定物种的完整基因组序列，包括染色体、线 粒体及其他遗传信息，通常为主装配版本。这些文件为基因组分析和比对提供基础数据。
  • 注释文件：基因组注释文件应 以 GTF 格式提供，包含基因组中基因、转录本、外显子及其他功能区域的详细信息。该文件标识基因的位置、类型（如“gene”、“transcript”、“exon”）及其相关属性（如“gene_id”、“gene_name”、“transcript_id”、“transcript_name”）。这些信息对理解基因组的功能和结构至关重要。

  对于可从 Ensembl 数据库 获取的物种，建议使用该处提供的文件。Ensembl 的 GTF 文件包含可选标签，便于过滤（通过 dnbc4tools tools mkgtf）。如果 Ensembl 无法提供所需物种的文件，则可以使用其他来源的 GTF 和 FASTA 文件。请注意，GTF 文件为必需，不支持 GFF 文件。基因组文件与注释文件需对应，GTF 文件格式要求为：对于单细胞 RNA 分析，GTF 文件至少需包含“gene”或“transcript”类型以及“exon”类型的注释，并且属性中必须包含“gene_id”或“gene_name”以及“transcript_id”或“transcript_name”。

## 下载参考基因组,这里以小鼠为例
curl-O https://ftp.ensembl.org/pub/release-115/fasta/mus_musculus/dna/Mus_musculus.GRCm39.dna.toplevel.fa.gz
## 下载注释文件
curl-O https://ftp.ensembl.org/pub/release-115/gtf/mus_musculus/Mus_musculus.GRCm39.115.gtf.gz

## 解压
gunzip  Mus_musculus.GRCm39.dna.toplevel.fa.gz
gunzip  Mus_musculus.GRCm39.115.gtf.gz

3.2 过滤GTF文件（可选）#

从 ENSEMBL 和 UCSC 等网站下载的 GTF 文件通常包含多种基因类型的基因。选择您研究中比较感兴趣的基因类型，过滤部分基因类型可以减少重叠的基因注释。与多个基因非唯一比对的 reads 会被过滤。

dnbc4tools

  • 校正 GTF 文件（可选）

GTF 文件格式要求为：对于单细胞 RNA 分析，GTF 文件至少需包含“gene”或“transcript”类型以及“exon”类型的注释，并且属性中必须包“gene_id”或“gene_name”以及“transcript_id”或“transcript_name”。存在内容缺失的 GTF 文件会导致主分析流程无法注释而报错。

dnbc4tools2.1.3/dnbc4tools tools mkgtf --action check --ingtf Mus_musculus.GRCm39.115.gtf --output Mus_musculus.GRCm39_corrected.gtf

软件会主动填补 gene 行和 transcript 行缺失的信息，会根据 gene_id 和 gene_name 以及 transcript_id 和 transcript_name 互相填补。

警告信息提示该位置存在多个基因信息，在分析时会导致过滤去重。

# 基因类型过滤
# dnbc4tools tools mkgtf --ingtf Homo_sapiens.GRCh38_corrected.gtf --output Homo_sapiens.GRCh38_filter.gtf --type gene_biotype

命令中我们可以添加参数 include 来获取需要的 gene 类型，默认是下面列出的基因型： - protein_coding - lncRNA/lincRNA - antisense - IG_V_gene - IG_LV_gene - IG_D_gene - IG_J_gene - IG_C_gene - IG_V_pseudogene - IG_J_pseudogene - IG_C_pseudogene - TR_V_gene - TR_D_gene - TR_J_gene - TR_C_gene

例如应用以上筛选来过滤，可以使用默认选项，也可以使用如下命令，类似 Cellranger 过滤步骤：

dnbc4tools2.1.3/dnbc4tools tools mkgtf --ingtf Mus_musculus.GRCm39_corrected.gtf --output Mus_musculus.GRCm39_filtered.gtf --type gene_biotype \
--include protein_coding,lncRNA,lincRNA,antisense,IG_V_gene,IG_LV_gene,IG_J_gene,IG_C_gene,IG_V_pseudogene,IG_J_pseudogene,IG_C_pseudogene,\
TR_V_gene,TR_D_gene,TR_J_gene,TR_C_gene

这将从原始未过滤的 GTF 文件生成一个过滤的 GTF 文件。在输出文件中，其他基因类型被排除在 GTF 注释之外。

3.4 准备Fastq文件#

  • 单样本：直接准备好对应的 cDNAfastq 文件和 oligofastq 文件即可
  • 多样本（可选）：为了简化每个样本单独生成主分析流程，可以使用配置文件来生成一个包含多个样本的主流程 shell 脚本
# dnbc4tools rna multi --list sample.tsv --genomeDir /opt/database/Homo_sapiens --threads 10

其中sample.tsv文件使用制表符 ( 分隔符。第一列包含样本名称，第二列包含 cDNA 文库测序数据，第三列包含寡核苷酸文库测序数据。多个 fastq 文件应以逗号分隔，R1 和 R2 文件应以分号分隔。

# sample1 /data/cDNA1_R1.fq.gz;/data/cDNA1_R2.fq.gz /data/oligo1_R1.fq.gz,/data/oligo4_R1.fq.gz;/data/oligo1_R2.fq.gz,/data/oligo4_R2.fq.gz 
# sample2 /data/cDNA2_R1.fq.gz;/data/cDNA2_R2.fq.gz /data/oligo2_R1.fq.gz;/data/oligo2_R2.fq.gz 
# sample3 /data/cDNA3_R1.fq.gz;/data/cDNA3_R2.fq.gz /data/oligo3_R1.fq.gz;/data/oligo3_R2.fq.gz

# cat sample1.sh

3.5 定量分析流程#

    } else {

    }

  }

4.4 Python自定义函数读取#

import pandas as pd
import scipy.io
import anndata
from scipy.sparse import csr_matrix
import os

def read_anndata_C4(path):
"""
    读取 10x Genomics MEX (Matrix Exchange) 格式的数据，并将其转换为 AnnData 对象。

    该函数假定 'path' 目录下包含三个标准文件：
    - matrix.mtx.gz (稀疏矩阵数据)
    - features.tsv.gz (特征/基因信息)
    - barcodes.tsv.gz (细胞条形码信息)

    Args:
        path (str): 包含 MEX 文件的目录路径。

    Returns:
        anndata.AnnData: 包含加载数据的 AnnData 对象。
    """

# 1. 读取稀疏矩阵数据 (matrix.mtx.gz)
# scipy.io.mmread 用于读取 Matrix Market 格式的稀疏矩阵文件 (.mtx)
# 默认 dtype 是 float64，将其转换为 float32 以节省内存
    mat = scipy.io.mmread(os.path.join(path, "matrix.mtx.gz")).astype("float32")

# 2. 矩阵转置 (Transpose)
# Matrix Market 格式的约定是 (Feature x Cell)，但 AnnData 要求 (Cell x Feature)
    mat = mat.transpose()

# 3. 转换为 CSR 稀疏矩阵格式
# CSR (Compressed Sparse Row) 格式是 AnnData 用于高效矩阵操作的首选格式
    mat = csr_matrix(mat)

# 4. 创建 AnnData 对象
# 使用转置并转换后的稀疏矩阵来初始化 AnnData 对象
# dtype="float32" 再次确保数据类型
    adata = anndata.AnnData(mat, dtype="float32")

# 5. 读取并设置特征/基因信息 (var)
# features.tsv.gz 文件通常包含基因ID和/或基因名称
    genes = pd.read_csv(os.path.join(path, "features.tsv.gz"), header=None, sep='\t')

# 将第一列（V1/0）的值作为 AnnData 的 var_names (特征名称)
    var_names = genes[0].values

# 确保特征名称是唯一的，这是 AnnData 的最佳实践
    var_names = anndata.utils.make_index_unique(pd.Index(var_names))
    adata.var_names = var_names

# 将基因 ID/符号作为 AnnData.var 的一个新列 'gene_symbols' 存储起来
# 即使 var_names 被唯一化了，原始的 ID 仍然有用
    adata.var['gene_symbols'] = genes[0].values

# 6. 读取并设置细胞条形码信息 (obs)
# barcodes.tsv.gz 文件包含细胞的唯一条形码
# 将第一列（V1/0）的值作为 AnnData 的 obs_names (观测名称，即细胞名称)
    adata.obs_names = pd.read_csv(os.path.join(path, "barcodes.tsv.gz"), header=None)[0].values

# 7. 最终检查和确保 var_names 唯一性 (尽管前面已经做过，这是一个安全步骤)
    adata.var_names_make_unique()

# 8. 返回构建好的 AnnData 对象
return adata
