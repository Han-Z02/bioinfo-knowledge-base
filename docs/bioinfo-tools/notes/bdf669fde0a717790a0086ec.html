不知道该用哪个时，按下面选。

我只有一个模糊研究方向，想先想清楚 deep-research socratic

我只想快速了解一个主题 deep-research quick
我要做文献综述 deep-research 或 academic-paper 调研用 lit-review；写成论文用 academic-paper lit-review

我要核查某些事实、引用或结论是否可靠 deep-research fact-check

我要先规划论文结构 academic-paper plan
我要写论文大纲 academic-paper outline-only

我要查引用格式、参考文献、DOI academic-paper citation-check

我要生成投稿用 AI disclosure academic-paper disclosure
我要模拟期刊审稿 academic-paper-reviewer full
我要快速看一下稿件质量 academic-paper-reviewer quick

一句话规则：

  • 还没形成论文，只是在查资料、澄清研究问题：用 deep-research。
  • 已经要写文章、摘要、大纲、回复审稿意见：用 academic-paper。
  • 已经有 manuscript，需要外部审稿视角：用 academic-paper-reviewer。
  • 想把整个流程从调研跑到定稿：用 academic-pipeline。

2. 怎么调用#

这些 skills 主要靠自然语言触发。你可以直接说任务，也可以显式指定 skill，显式指定通常更稳。

2.1 Codex 中调用#

示例：

使用 deep-research，帮我调研单细胞转录组中 doublet detection 方法的最新进展，输出文献矩阵和关键争议。

使用 academic-paper，基于我提供的结果写一篇生信方法学论文，先进入 plan 模式，不要直接写全文。

使用 academic-paper-reviewer，按 Nature Methods 风格审稿这篇 manuscript，重点看 novelty、benchmark 和 reproducibility。

2.2 Claude Code 中调用#

WSL 里的 Claude Code 会从 ~/.claude/skills 读取 skills。进入 claude 后直接发：

Use academic-pipeline for an end-to-end research-to-paper workflow on this project.

或中文：

请用 academic-pipeline 帮我从研究调研到论文定稿跑完整流程。主题是：空间转录组数据中的细胞类型反卷积方法比较。

2.3 建议的固定开场模板#

请使用 [skill 名称]。

领域：[例如：bioinformatics / single-cell RNA-seq / bulk RNA-seq / spatial transcriptomics]
已有材料：[论文 PDF / 结果表 / 图 / 代码 / 数据链接 / 参考文献]
目标输出：[文献矩阵 / 大纲 / manuscript / review report / revision roadmap / LaTeX]
约束：[语言、字数、期刊、引用格式、是否需要联网核查、是否要保守]

3. deep-research：深度研究与文献调研#

deep-research 适合在写论文之前使用，也适合做事实核查、系统综述、证据综合和研究方向澄清。

3.1 适用场景#

  • 你有一个宽泛主题，需要收敛成可研究的问题。
  • 你要做一个领域综述、技术路线调研或政策/方法分析。
  • 你需要比较多个方法、数据库、工具或实验设计。
  • 你要核查论文中的 claim 是否被文献支持。
  • 你要做 PRISMA systematic review 或 meta-analysis。
  • 你要把调研结果交给 academic-paper 写成论文。

3.2 模式表#

Mode 适合任务 主要输出
socratic 研究方向模糊，需要引导式提问 Research Plan Summary、INSIGHT collection、候选 RQ
full 有明确 RQ，需要完整研究报告 APA 7.0 research report，通常 3000-8000 words
quick 快速了解主题 500-1500 words research brief
review 评估一段已有文本或论文 Reviewer report
lit-review 文献综述与证据整合 Annotated bibliography、synthesis、gap analysis
fact-check 核查具体事实、数据、引用 Verification report
systematic-review 系统综述、meta-analysis、PRISMA PRISMA report、RoB、GRADE、forest plot data

3.3 工作流#

deep-research 默认分 6 个阶段：

  1. Scoping：把主题变成研究问题，评估 FINER 标准。
  2. Methodology：设计研究范式、方法、数据策略和分析框架。
  3. Investigation：系统检索、筛选文献、建立 annotated bibliography。
  4. Verification：核查来源质量、证据等级、掠夺性期刊风险和利益冲突。
  5. Synthesis：主题综合、矛盾证据处理、gap analysis。
  6. Report：写成 APA 7.0 报告，并经过 editorial / ethics / devil's advocate 检查。

3.4 常用提示词#

模糊选题澄清

请使用 deep-research 的 socratic 模式。
我对单细胞多组学整合感兴趣，但还没有明确研究问题。
请通过提问帮我收敛到 2-3 个可研究、可发表的方向。
每轮只问最关键的问题，不要直接替我下结论。

生信主题快速调研

请使用 deep-research 的 quick 模式。
主题：bulk RNA-seq 差异表达分析中 DESeq2、edgeR、limma-voom 的适用场景。
输出：
1. 方法差异表
2. 适用/不适用场景
3. 常见误用
4. 5-10 篇关键参考文献

完整文献综述

请使用 deep-research 的 lit-review 模式。
主题：spatial transcriptomics 中 cell type deconvolution 方法。
要求：
1. 按方法类别组织：reference-based、reference-free、probabilistic、deep learning
2. 给出每类代表工具、输入输出、假设和局限
3. 输出 literature matrix
4. 标出尚未解决的问题和潜在研究切入点

事实核查

请使用 deep-research 的 fact-check 模式。
核查以下 claim 是否成立：
"scVI 在所有单细胞批次校正任务中都优于 Harmony 和 Seurat integration。"
请逐条检查：
1. 是否过度概括
2. 支持和反对证据
3. 适用条件
4. 更准确的表述
5. 可引用文献

系统综述 / Meta-analysis

请使用 deep-research 的 systematic-review 模式。
主题：机器学习模型预测肿瘤免疫治疗响应的外部验证表现。
请先输出 protocol：
1. PICO/PECO
2. 数据库和检索式
3. inclusion / exclusion criteria
4. 主要和次要 outcome
5. RoB 工具
6. 是否适合 meta-analysis 的判断标准
等我确认后再继续。

3.5 输出如何交给 academic-paper#

完成调研后，可以直接说：

基于刚才 deep-research 的 RQ Brief、Methodology Blueprint、Annotated Bibliography 和 Synthesis Report，
请切换到 academic-paper 的 plan 模式，帮我规划一篇 manuscript。

推荐保留的交接材料：

  • Research Question Brief
  • Methodology Blueprint
  • Annotated Bibliography
  • Synthesis Report
  • Evidence / Literature Matrix
  • INSIGHT Collection（如果用了 socratic）

4. academic-paper：论文写作、修改和格式化#

academic-paper 是写作主力。它不是单纯续写文本，而是把论文写作拆成配置、文献、结构、论证、正文、引用、摘要、内部审阅、格式化等阶段。

4.1 适用场景#

  • 从研究问题和结果出发写完整 manuscript。
  • 写论文大纲、章节结构、argument blueprint。
  • 写摘要、关键词、投稿声明。
  • 基于 reviewer comments 修改文章。
  • 把无结构审稿意见整理成 revision roadmap。
  • 查引用、修参考文献、转换 citation style。
  • 生成 LaTeX、DOCX、PDF、Markdown。

4.2 10 个模式#

Mode 触发语义 输出
full Write a paper / 写论文 完整论文 draft，必要时含图表代码
outline-only Paper outline / 论文大纲 详细大纲、evidence map
revision Revise paper / 修改论文 修订稿、修改记录、response to reviewers
abstract-only Write abstract / 写摘要 中英双语摘要和关键词
lit-review Literature review paper 文献综述型论文材料
format-convert 转 LaTeX / DOCX / citation style 格式化文档和引用格式转换
citation-check Check citations / 查引用 Citation error report
plan Guide my paper / 帮我规划论文 Chapter Plan、INSIGHT Collection
revision-coach Parse reviews / 收到审稿意见 Revision Roadmap、tracking template、response skeleton
disclosure AI disclosure for venue 期刊/会议投稿用 AI 使用声明

4.3 写作流程#

full 模式通常分 8 个 phase：

Phase 内容 产物
0 Configuration Paper Configuration Record
1 Literature Search Strategy、Source Corpus
2 Architecture Paper Outline、Evidence Map
3 Argumentation Argument Blueprint
4 Drafting Complete Draft
5a Citations Citation Audit Report
5b Abstract Bilingual Abstract、Keywords
6 Peer Review Internal Review Report
7 Format LaTeX / DOCX / PDF / Markdown

关键规则：

  • Phase 0 的 Paper Configuration Record 需要用户确认。
  • Phase 2 的 outline 需要用户确认后再继续写正文。
  • 引用必须核查，不能保留无法确认的文献。
  • revision 最多 2 轮，无法解决的问题进入 Acknowledged Limitations。
  • 每篇论文都应包含 Data Availability、Ethics、Author Contributions、COI、Funding、AI disclosure 等声明。

4.4 写作前最好准备什么#

最少需要：

  • 论文主题或研究问题
  • 学科领域
  • 目标文章类型：IMRaD、review、case study、theoretical paper、policy brief、conference paper 等
  • 目标期刊或会议
  • 字数范围
  • 引用格式：APA 7、Chicago、MLA、IEEE、Vancouver
  • 输出格式：Markdown、LaTeX、DOCX、PDF
  • 已有材料：结果表、图片、代码、参考文献、实验设计、数据来源

生信 manuscript 推荐额外提供：

  • 数据来源：GEO / SRA / TCGA / ArrayExpress / 自有数据
  • accession number
  • 样本分组、纳入排除标准
  • 预处理流程
  • 软件版本和参数
  • 统计方法和多重检验校正
  • 图表列表
  • 代码仓库或可复现性说明

4.5 常用提示词#

先规划，不直接写全文

请使用 academic-paper 的 plan 模式。
主题：基于单细胞 RNA-seq 的肿瘤微环境细胞互作分析。
已有材料：初步 UMAP、marker gene 表、cell-cell communication 分析结果、20 篇参考文献。
目标：规划一篇偏生信应用研究的 manuscript。
要求：
1. 先帮我确认 paper type 和目标期刊层级
2. 输出完整大纲和每节核心论点
3. 标出哪些结果还不足以支撑结论
4. 不要直接写全文

从结果写完整论文

请使用 academic-paper 的 full 模式。
论文类型：bioinformatics application paper，IMRaD 结构。
主题：利用公开 bulk RNA-seq 数据构建肝癌免疫相关 prognostic signature。
已有材料：
- 差异基因表
- Cox/LASSO 模型结果
- KM、ROC、nomogram 图
- immune infiltration 分析结果
- validation cohort 结果
目标期刊：BMC Bioinformatics 或 Frontiers in Immunology 风格。
引用格式：Vancouver。
输出：Markdown 初稿，随后再转 LaTeX。
要求：保守表述，避免夸大 biomarker 的临床价值。

写摘要

请使用 academic-paper 的 abstract-only 模式。
根据下面 manuscript 内容写中英双语摘要。
要求：
1. 英文 250 words 左右
2. 中文 400-500 字
3. 结构包含 Background、Methods、Results、Conclusion
4. 给出 5-7 个 keywords
5. 不要添加正文没有支持的结果

处理审稿意见

请使用 academic-paper 的 revision-coach 模式。
下面是 reviewer comments，请先整理成 Revision Roadmap。
要求：
1. 按 reviewer 和 issue 编号
2. 标注 CRITICAL / MAJOR / MINOR
3. 判断每条意见是否合理
4. 给出建议回应策略
5. 输出 response letter skeleton

改稿

请使用 academic-paper 的 revision 模式。
输入材料：
1. 原 manuscript
2. Reviewer comments
3. Revision Roadmap
4. 我已经新增的分析结果
要求：
1. 只修改与审稿意见相关的部分
2. 不要无根据扩展结论
3. 对每条 reviewer comment 生成 response
4. 标出 manuscript 中对应修改位置

查引用

请使用 academic-paper 的 citation-check 模式。
检查这篇 manuscript 的所有引用。
要求：
1. 核查 DOI、标题、作者、年份是否匹配
2. 检查正文引用和 reference list 是否一一对应
3. 标出疑似不存在或信息混合的引用
4. 输出需要替换或删除的参考文献清单

生成 AI disclosure

请使用 academic-paper 的 disclosure 模式。
目标期刊/会议：Nature Methods。
AI 使用情况：
- 用 AI 辅助整理文献
- 用 AI 辅助润色英文
- 统计分析和结论由作者完成并人工核查
请生成投稿用 AI usage disclosure，并说明适合放在 manuscript 的哪个位置。

5. academic-paper-reviewer：模拟审稿#

academic-paper-reviewer 用来模拟完整 peer review。它会配置 5 个角色：Editor-in-Chief、methodology reviewer、domain reviewer、cross-disciplinary perspective reviewer、Devil's Advocate，最后合成 editorial decision 和 revision roadmap。

5.1 适用场景#

  • 投稿前想知道 manuscript 的主要硬伤。
  • 需要模拟目标期刊审稿风格。
  • 想专门查方法学、统计学或可复现性问题。
  • 收到 revision 后，想检查回复是否真正解决问题。
  • 想把 review 结果交给 academic-paper revision 修改。

5.2 6 个模式#

Mode 适合任务 输出
full 完整预审 5 份 review report、editorial decision、revision roadmap
re-review 检查修回稿 traceability matrix、residual issues、新 decision
quick 快速质量评估 EIC quick assessment、key issues
methodology-focus 方法/统计专项审查 深入 methodology review
guided 通过提问理解问题 Socratic guided review
calibration 校准审稿器可靠性 FNR/FPR、balanced accuracy、confidence disclosure

5.3 输出内容#

完整 review 通常包括：

  • Reviewer Configuration Card
  • EIC Review
  • Methodology Review
  • Domain Review
  • Perspective Review
  • Devil's Advocate Report
  • Editorial Decision Letter
  • Revision Roadmap

Devil's Advocate 特别重要，它会找：

  • 最强反驳
  • 逻辑链断点
  • cherry-picking
  • confirmation bias
  • alternative explanations
  • stakeholder blind spots
  • "So what?" significance 问题

关键规则：

  • Reviewer 只读稿件，不直接修改 manuscript。
  • Synthesizer 不能编造 reviewer 没提过的问题。
  • Devil's Advocate 发现 CRITICAL 问题时，最终 decision 不能是 Accept。
  • 每条 criticism 应该有具体位置、问题说明和修改建议。

5.4 常用提示词#

投稿前完整审稿

请使用 academic-paper-reviewer 的 full 模式。
目标期刊风格：Genome Biology / Nature Communications 水平。
稿件类型：bioinformatics application paper。
重点审查：
1. novelty 是否足够
2. benchmark 是否公平
3. validation cohort 是否充分
4. 统计方法是否合理
5. 结果是否过度解释
6. 代码和数据可复现性
请输出 editorial decision 和按优先级排序的 revision roadmap。

方法学专项审查

请使用 academic-paper-reviewer 的 methodology-focus 模式。
只审查方法、统计和可复现性。
请重点看：
1. 差异分析设计是否合理
2. batch effect 是否处理得当
3. 多重检验校正是否正确
4. 模型训练/验证是否有 data leakage
5. 图表和统计报告是否符合规范

修回稿复审

请使用 academic-paper-reviewer 的 re-review 模式。
输入：
1. 第一轮 Revision Roadmap
2. 修订稿
3. Response to Reviewers
请逐条判断：
1. 作者声称已解决的问题是否真的解决
2. 是否产生新问题
3. 是否还有 blocking issue
4. 给出新的 editorial decision

快速预审

请使用 academic-paper-reviewer 的 quick 模式。
给这篇 manuscript 做 15 分钟快速预审。
输出：
1. 最可能导致 desk reject 的 5 个问题
2. 最值得保留的 3 个优点
3. 投稿前必须补的分析
4. 是否建议进入完整 review

6. academic-pipeline：完整研究到论文流程#

academic-pipeline 是调度器，不自己写内容，而是按阶段调用 deep-research、academic-paper、academic-paper-reviewer 和完整性核查 agent。

6.1 适用场景#

  • 你想从一个研究主题一路做到投稿前定稿。
  • 你想强制加入引用核查、完整性核查、模拟审稿、复审等质量关卡。
  • 你有已有论文，想从中途进入：review、revision、finalize。
  • 你要保留过程记录，方便复盘人机协作和版本变化。

6.2 10 个阶段#

Stage 名称 调用对象 产物
1 RESEARCH deep-research RQ Brief、Methodology、Bibliography、Synthesis
2 WRITE academic-paper Paper Draft
2.5 INTEGRITY integrity_verification_agent 引用、数据、claim 完整性核查
3 REVIEW academic-paper-reviewer 5 份 review + decision + roadmap
4 REVISE academic-paper revision Revised Draft、Response
3' RE-REVIEW academic-paper-reviewer re-review 修订验证报告
4' RE-REVISE academic-paper revision 第二轮修订稿
4.5 FINAL INTEGRITY integrity_verification_agent 最终完整性核查
5 FINALIZE academic-paper format-convert MD / DOCX / LaTeX / PDF
6 PROCESS SUMMARY orchestrator Paper Creation Process Record

6.3 状态机#

flowchart TD
    A["Stage 1: Research"] --> B["Stage 2: Write"]
    B --> C["Stage 2.5: Integrity Check"]
    C -->|PASS| D["Stage 3: Review"]
    C -->|FAIL| B
    D -->|Accept| H["Stage 4.5: Final Integrity"]
    D -->|Minor/Major Revision| E["Stage 4: Revise"]
    D -->|Reject| B
    E --> F["Stage 3': Re-review"]
    F -->|Accept/Minor| H
    F -->|Major| G["Stage 4': Re-revise"]
    G --> H
    H -->|PASS| I["Stage 5: Finalize"]
    H -->|FAIL| G
    I --> J["Stage 6: Process Summary"]

6.4 Checkpoint 规则#

academic-pipeline 的核心特点是不会一路自动冲到底，而是在关键阶段要求确认。

必须确认的点：

  • 每个 stage 完成后都要确认是否进入下一阶段。
  • Stage 2.5 和 Stage 4.5 的 integrity check 不能跳过。
  • Review decision 后必须明确选择下一步。
  • Finalize 前必须确认内容正确。
  • 如果质量下降、引用不可靠或 reviewer concern 没处理完，应该暂停。

6.5 断点恢复#

高级用法：

export ARS_PASSPORT_RESET=1

启用后，pipeline 会把某些完整 checkpoint 记录成可恢复边界。新会话中可用：

resume_from_passport=<hash>

适合长项目跨会话继续，尤其是完整论文流程很长时。

7.1 单细胞论文选题到写作#

请使用 academic-pipeline。
项目方向：单细胞 RNA-seq 分析肿瘤免疫微环境。
已有材料：
- Seurat object
- 细胞注释结果
- marker gene 表
- UMAP / violin / dotplot
- pathway enrichment
- cell-cell communication 结果
目标：形成一篇应用型生信论文。
流程要求：
1. 先用 deep-research 检查该方向 novelty 和可发表切入点
2. 再用 academic-paper plan 模式设计 manuscript 结构
3. 写作时保守表述，不把相关性解释成因果
4. review 阶段重点检查细胞注释、batch effect、样本量和验证不足

7.2 预后模型论文防止过度包装#

请使用 academic-paper-reviewer 的 methodology-focus 模式。
稿件主题：基于 TCGA + GEO 构建肿瘤预后 signature。
请重点检查：
1. 训练集/验证集是否独立
2. feature selection 是否 data leakage
3. LASSO/Cox 的流程是否规范
4. KM / ROC / C-index 是否充分
5. nomogram 是否有 calibration
6. immune infiltration 结论是否过度解释
7. 是否缺少外部验证或实验验证
输出按 CRITICAL / MAJOR / MINOR 分类。

7.3 RNA-seq 方法比较综述#

请使用 deep-research 的 lit-review 模式。
主题：bulk RNA-seq 差异表达分析方法比较。
比较对象：DESeq2、edgeR、limma-voom、sleuth。
输出：
1. 方法假设与模型差异
2. 适用样本量和数据分布
3. normalization 策略
4. dispersion estimation 差异
5. 典型 benchmark 文献
6. 实践建议和常见误区
最后给出可转化为 review paper 的大纲。

请使用 academic-paper-reviewer 的 full 模式。

9. 质量与完整性检查清单#

9.1 文献和引用#

  • 每条关键 claim 都有来源。
  • 每条参考文献真实存在。
  • DOI、标题、作者、年份匹配。
  • 正文 citation 和 reference list 一一对应。
  • 没有把多篇论文信息混成一条引用。
  • 没有只引用支持结论的文献，也报告反向证据。
  • 旧文献被标注为 seminal 或被更新文献补充。

9.2 生信分析#

  • 数据来源和 accession number 可追溯。
  • 样本纳入排除标准清楚。
  • 软件版本、参数、阈值写明。
  • normalization、batch correction、QC 标准清楚。
  • 差异分析有多重检验校正。
  • 模型训练和验证没有 data leakage。
  • 外部验证和敏感性分析充分。
  • 结论没有把相关性写成因果。
  • 图表能从数据或代码复现。

9.3 写作#

  • Introduction 的 gap 明确，不是泛泛背景。
  • Methods 具体到可复现。
  • Results 只报告结果，不夹带过度解释。
  • Discussion 区分发现、解释、局限和展望。
  • Limitations 明确。
  • Data Availability、Code Availability、Ethics、COI、Funding、Author Contributions 齐全。
  • AI disclosure 与目标期刊政策匹配。

9.4 审稿前#

  • 用 academic-paper citation-check 查一遍引用。
  • 用 academic-paper-reviewer methodology-focus 查方法。
  • 用 academic-paper-reviewer full 做一次完整预审。
  • 把 CRITICAL / MAJOR 问题处理后再投稿。
  • 修订后用 re-review 检查是否真的回应了 roadmap。

10. 常见坑和规避#

常见坑 后果 推荐处理
直接让 AI 写全文，不先确认 RQ 和 outline 文章结构虚、论点散 先用 deep-research socratic 或 academic-paper plan
引用看起来像真的但没核查 可能出现假引用 必跑 citation-check 或 pipeline integrity
综述只列论文，不综合矛盾证据 像 annotated bibliography 用 deep-research lit-review 要求 synthesis 和 contradiction handling
reviewer comment 全盘接受 修改可能偏离论文核心 用 revision-coach 判断合理/不合理
预后模型论文过度宣称临床价值 审稿高风险 明确要求保守表述和外部验证检查
单细胞分析缺少 batch/QC/annotation 说明 方法学硬伤 用 methodology-focus 专审
pipeline 太长导致上下文压力 中途质量下降 使用 checkpoint、保存 Material Passport、必要时新会话 resume

11.1 从想法到论文#

  1. deep-research socratic：澄清研究方向。

  9. academic-paper-reviewer re-review：检查修改是否充分。

  11. academic-paper disclosure：生成 AI disclosure。
