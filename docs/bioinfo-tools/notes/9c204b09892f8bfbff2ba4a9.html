摘要LLM 归库摘要

  • 核心内容： 这篇微信文章介绍 OmicOS 正式版：一个围绕 OmicVerse 生态构建的本地 AI 科学家/AI4Bio 分析平台，强调自动下载数据、复现论文分析、生成可追溯 notebook，并通过多专科 agent 覆盖组学、病理、ImageJ、Pymol 与分子动力学等场景。
  • 适用场景： 需要低门槛、本地化、可复现地完成组学分析、论文复现、benchmark 评估、单细胞/空间组学/微生物组/病理图像等多模态生物医学分析时，可作为候选工具或方法学参考。
  • 输入： 论文 PDF、公开数据库数据（如 GEO、cellxgene）、用户本地组学数据、notebook、包教程/源码、实验设计与分析问题。
  • 输出： 可复核 notebook、出版级图表、差异基因与富集结果、方法学描述、数据/代码/文献可追溯的分析报告，以及可组合的分析路径与 agent 执行记录。
  • 关键参数/步骤： 重点关注 OmicOS 桌面端/网页版/CLI、npm install -g @omicverse/omicos 安装方式、OmicVerse 统一 API、RebuildR 将 R 包重构为 Python 包、PortBuild 将教程/源码/notebook 转为 Agent/Skill、BixBench/BiomniBench/OmicBench 三类评测。
  • 常见错误： 可能把产品宣传性 benchmark 直接当作独立验证结论；忽略本地算力、依赖安装、API key/模型费用、HPC/SSH 配置、不同组学任务的可复现性差异；微信图片中的关键结果尚未本地化保存。
  • 与口腔生信连接： 可考虑用于牙周炎、OSCC、口腔微生物、空间转录组或病理切片项目的自动数据下载、单细胞注释、轨迹/富集/空间映射、HE 特征提取和论文复现；但进入正式课题前应先用公开口腔数据集小规模试跑。

「 时清日长，帆悬江阔 」

半个月前，OmicVerse在Github上突破1000🌟！

准备了很久的千🌟的福利，终于要端上来了。

即使在benchmark上全线领先；即使在功能上全面覆盖，即使在价格上全面低于同行 ，但我还是不知道怎么跟大家去介绍OmicOS。

三月份，我撰写了一篇“ 第一作者解读｜OmicClaw下一代组学研究的AI分析系统 ”，收获了6000多个阅读量，但在不断的迭代维护过程我发现，它其实没解决AI4Bio的根本问题。 生物医学需要的不是手机对话，而是可靠好上手的分析，数据本地化隐私化的分析，人人可学的生物学分析。 没有任何门槛，包括安装门槛。

今天，OmicOS 正式版（ https://omicos.cn/ ）发布，我们希望，生物学家从此不再需要到处求人合作分析数据。

Steorra

OmicOS在BioRxiv上线了

在2024年底，OmicOS项目立项，但中途一度夭折，因为Claude Code，Codex，opencode等工具的出现，似乎已经将Agent智能体的蓝海填满了。我一直在问自己，如果我继续做AI科学家，那么能做的比御三家的Agent产品要好吗？

答案是肯定的，我们不仅能做得更好，还要同时奠定AI4Bio时代的基础设施

scverse生态，也曾经希望有一个Agent智能体，能将所有scverse下的包收纳到一个体系下，为此他们找到了Biomni来做这件事。但最后，Biomni给自家的Phylo撰写了一系列的Skill去调用scverse和R语言的包，这事儿似乎也就不了了之了。

但omicverse生态不同，我们真正意义上，将生物学所有的组学相关的算法，纳入了同一个体系下，我们统一了变量，统一了函数，这在无形中，构建出了AI时代Agent真正的数字资产， 一个统一的生物学的基础设施 。

分析能力有多强呢？ 通俗一点来说，给定一篇pdf，OmicOS可以自动下载数据，然后自动复现论文里的所有分析和图表

OmicVerse现在涵盖了 基因组学，转录组学，蛋白组学，代谢组学，微生物组学，表观基因组学，空间转录组，单细胞转录组，分子靶点对接分析，前沿可视化 等所有跟组学相关的内容，你没看错，是所有。并且统一了R下的Bioconductor/CRAN下的算法包，通过RebuildR将其重构成 更快，更准 的Python包。

到此，一个AI时代的基础设施，初步形成。

OmicOS的五层架构

Benchmark测评#

在OmicClaw这篇论文，我犯了一个错误，没有横向，充分地在生物学benchmark上去对比claude code，codex，biomni等Agent的能力，而是仅对比了OmicVerse+gpt5.5前后的能力差，并且任务也选的只有10个简单任务。

没有人相信你是世界最好，你不是最好谁又会用呢？

我们首先选取了BixBench-Verified-50，这是FutureHouse提出，Biomni精选的50道生物学分析问题，用于评估AI智能体的数据分析能力。

BixBench测评能力

在50道题中，有45道题被OmicOS完美解决，而剩下的5道题，似乎OmicOS也答对了，但是答案的选取标准可能有一些问题，我们不敢说OmicOS能解决所有的生物学分析问题，但我们证明了一个事儿，那就是 OmicOS+deepseek-v4-pro 的组合，是目前世界上最具有竞争力，最便宜的分析框架体系。

BixBench错题分析

当然，BixBench是面向结果的，而在真实的生物学分析里，是面向过程的，很多时候，我们需要去评估Agent智能体是否正确选择了方法，是否正常处理了数据，是否进行了可靠的生物学解释等，因此Phylo推出了一个新的Benchmark——BiomniBench，这是一个同时面向过程和结果的AI智能体的评估基准测试，过程的评价使用Gemini进行打分。

BiomniBench结果

我们可以看见在BiomniBench的论文里的100道题下，Claude Code+Opus 4.7的得分是72.7，Codex+GPT5.5的得分是67，而Qwen，Kimi仅有60分，看起来都不高对吧。

由于BiomniBench在HuggingFace上开放了其中的50道题，我们也因此能评估OmicOS与不同的大模型基座之间的能力， 很有趣的是，OmicOS+ds4-pro的得分，也来到了72，价格仅是Claude Code+Opus的1/10。而OmicOS+GPT5.5的得分，来到了78.2，排除了BiomniBench上的错题，更是来到了81.2 。

BiomniBench的详细任务

需要承认的是，目前国产大模型与国外前沿模型还是有一定差距，无论是长程能力的执行又或者是响应速度，Prompt的遵从性。

但这也让我们看到了希望，原来做好Harness，是真能在垂类任务上追赶，甚至反超国外前沿大模型（注：GLM5.2没测是因为我抢不到Coding Plan）。

实际上你会发现，到这里， 我们似乎还没介绍OmicOS的架构 。下面要介绍的基础设施，也不是OmicOS架构的设计。

OmicVerse对模型能力的提升#

作为一个学术研究，我们既然说是 “重构AI4Bio的基础设施” ，那么少不了对模型添加OmicVerse前后的能力变化。为此我们不鼓吹OmicOS有多好，我们采用Mini-SWE-Agent，这是一个仅有100行代码的最简Agent。

由于BixBench和BiomniBench在组学任务上没有覆盖完全，仅有转录组，GWAS等计算友好的类别，为此我们构建了OmicBench，这是一个涵盖了40个任务的基准测试，包含了7大组学的任务，在未来我们会继续扩充更多的内容进入该基准测试。

OmicBench概览

我们发现，在结合了OmicVerse这个AI4Bio的基础设施后， 本地开源小模型Qwen3.6-35b-A3b的能力提升了34.2%，直追大模型如Deepseek-V4-Pro。 一方面，这说明我们实现了模型平权和隐私保护，尤其是生物医学这块，我们可以完全让分析数据不脱离用户自己的电脑，这听起来很疯狂，但我们确实做到了。

模型能力的提升

另一方面，这表明，对于绝大多数生物学分析任务而言，并不需要领域内最好的大模型， 而缺的仅是一个真正意义上的AI4Bio的基础设施 。

模型提升的细则

行文至此，还是很感慨，四年前的满腔热情，竟有希望成为AI4Bio一个重要的基础设施。

重构R语言生态体系#

记得在两年前还是三年前，与一位Bioconductor的中国区代表交流过，那会儿Bioconductor还是生物信息学分析至关重要的一个社区，靠着庞大的R语言支持构建了坚实的用户壁垒。

而在现在，用户根本不用去学R语言，而是让AI去调用R包去完成分析，那么这就自然而然引出一个问题

R语言的算法包，相比Python/Rust，太慢了

当用户开始关心运行速度的时候，就会自然而然转向更快的Python生态体系，但是用户又不希望丢失R语言生态的算法，这自然而然地引出了一个两难的问题， 如果能在Python里也使用R包就好了

这里指的不是通过Python使用rpy2等wrapper去调用R包，而是真正意义上使用Python的标准库进行重新实现。在Agent时代，这似乎并不是什么难事儿，但是缺乏一个标准， 怎样重构的R包，才是好用的Python包？

我在两个月前发出了一个倡议，重构R语言生态体系（微信公众号链接），林林总总有十几个小伙伴响应了我的号召，我们在不到一个月的时间内，重构了58个R包，使其变成完全的Python包。

并且我们也归纳总结出了一个通用的Agent转换协议RebuildR，该协议类似强化学习，主要分为三个步骤，（1）提出候选的重构算法设计思路；（2）每一个思路进行运行时间和准确性的评估；（3）迭代继续优化。

RebuildR协议

听起来很简单，实际上这很工程学。对于重构后的算法，其实我并不需要结果完全一致，也可以是精度上的一致，例如小于1e7，还可以是数学上的子集优化，这意味着，我只需要找到数学上的近似优化，就可以不仅利用Python的运行速度优势，还可以利用数学上的计算优势，这才是真正意义上的，重构R/Python社区。

我们进行了7种拟时序算法的R/Python实现的基准测试，发现RebuildR重构后的算法，不仅运行速度可以是原来的几十倍，准确度甚至略有提升。

Benchmark对比拟时序

并且我们还将这些重构算法的进化迭代路径展现出来，发现重构并不是一簇而就的，而是像进化一样，有一个演化过程，这也反证我们RebuildR不是简单的算法重构，而是一个工程上，数学上都有意义的执行体系。

PseudoTimeFate应用

并且OmicVerse可不是仅仅重构算法成Python包这么简单，我们既然构建的是基础设施， 那么必定有一个统一的上层API函数，去容纳不同的算法包。

在这个例子里，我们演示的是 omicverse.single.PseudotimeFate 和 omicverse.single.Traj ，PseudotimeFate支持任何拟时序结果作为输入，可以进行谱系的预测，从而执行时序驱动基因的发现，而Traj支持method=‘任意拟时序算法名’，自动计算出pseudotime。

这对Agent来说，是一个知识体系的基础设施的重构，AI再也不会写出混淆的函数参数代码，还能 一键完成多种拟时序分析对比然后找出最好的一种 。

OmicOS与阿尔茨海默症新机制#

一个月前的Nature三连发，其中Robin提出了一个科学新发现的探索逻辑，组合不同文献里的知识，找出遗漏的内容，我认为这仅是第一层。

而在OmicOS中，由于都在同一个生态体系内，因此， 我们可以直接组合不同算法，结合不同算法对于数据挖掘的优势，将一个数据所有维度的内容分析出来 ，我认为这是探索新科学发现的第二层。

第一层再怎么组合，也组合不出没进行过数据挖掘和分析的内容

生态模块组合Agent

这其实也是一个可以单独拿出来发顶会的设计，我们将OmicVerse生态抽象成16个套件，然后自由组合不同的套件，我们既可以得到“质控-预处理-细胞注释”这种传统的分析路径，也可以得到“空间单细胞定位-空间性状挖掘”这种需要跨领域知识的分析路径，通过打分Agent，我们找出一条或多条能充分挖掘该数据的分析思路，然后再交给OmicOS执行。

阿尔茨海默症图谱

于是我们看见，OmicOS自动从GEO和cellxgene等数据库来源，跨越5个研究， 下载并构建了一个跨越10个年龄段的小鼠单细胞全器官图谱 ，然后调用CellTrek，CMAP等方法，将单细胞映射到空间位置上，然后使用gsmap将AD性状解析道空间位置上，将gsmap的结果从组织层提升到了细胞类型层。

后续的分析由于我不是GWAS专业的，所以基本上都是Agent自行提出分析思路，我点击同意，然后自动下载数据，自动安装算法包，自动分析进行的，包括AD性状基因跟空间上皮marker的共定位（为了确定真是上皮细胞相关）。

基因共定位

很有趣，我们下一步就会开展相关的小鼠实验验证这一生物学发现的真实性了。

OmicOS可扩展到任意科学发现#

刚刚提出的很多内容，都是基于OmicVerse生态下的组学分析。实际上，我们的愿景是要打造一个真正的AI科学家，那么由于开发团队的限制，还有很多功能我们没法导入OmicVerse生态，例如HE病理图像处理。

我们构建了PortBuild， 这是一个可以将任意包的教程，源码，Notebook转换成Agent/Skill的工具体系 ，我们利用了SkillOPT的优化思想，将Skill当成一个神经网络去训练，通过迭代优化，自动将包变成了Agent/Skill，然后我们用OmicOS调用LazySlide去看看效果。

PortBuild概览

我们发现，OmicOS因此有了相当完善的HE分析能力，可以做特征提取，找出病理相关的特征，也可以调用OmicVerse本来的HE预测基因表能力去生成空间转录组学数据，还可以同时分析100及以上的HE病理切片大队列，找出生存分析相关的特征因素。

大队列处理

OmicOS 到底是什么？#

我认为OmicOS是一个可成为任何人助手的AI科学家，并且分析完全在本地，你无需为数据上传而担忧，还可以自定义API来调用不同大模型的能力。

我是希望它成为科学家的Claude Code平替，甚至在未来成为上位替代

你的AI科学家#

把公开数据、实验设计、文献证据和分析代码通通交给 OmicOS。它直接基于真实组学数据展开分析、提出假设，并产出每一步都可复核、可复现的 notebook，让你无需把复杂的科研问题强行压缩成一条提示词。

交付可复现的科研成果#

产出你可以直接评审、复核并写进论文的分析报告、出版级图表、差异基因与富集结果、方法学描述，以及每一步都能重跑的 notebook——不是一段聊天回答，而是带代码、带证据、可回溯的完整工作成果。

和 AI 共享同一个 notebook#

OmicOS 把分析放进一个活的 notebook：你和 AI 共享同一个 Python 内核和同一批变量，AI 能直接读你的 adata、跑下一格、画图，你也能随时改一行代码接着往下走。不是黑箱给答案，而是每一步都是真实、可编辑、可重跑的代码。

每个结论，都能查到它从哪来#

OmicOS 不会凭空给你一个数字。每一条结论都绑定生成它的代码格、用到的数据和引用的文献——点一下就能回溯到那一格重跑、那篇文章。没有跑过的代码，就没有结论；讲不清来源的，它会说"不确定"，而不是编一个。完整的轨迹分析可溯源，可追踪。

不仅是一个 AI，更是一支组学团队#

一个任务进来，编排智能体把它拆给合适的专家智能体：质控、预处理、注释、轨迹、富集、空间、微生物组……40+ 专科 agent、152 个精选分析技能各司其职。不归自己管的活，专家智能体会直接说"这不是我的范围"并转交给其他人，而不是硬答，这与真实的科研协作一样。

你的数据，不出你的机器#

OmicOS 运行在你的本地计算机，我并不同意phylo的思想，本地分析完全是可行的，数据上传风险很大，在omicos里，我们起一个 127.0.0.1 上的本地内核，所有计算、变量、图表和 notebook 都留在.omicos/ 工作区里。处理临床或未发表数据时，你不必把它交给任何云端。需要算力时，同一套还能在 HPC 上以终端模式（omicos cli）通过 SSH 直接跑。

持续更新的工具体系#

我们在OmicOS 1.0引入了单细胞数据查看器，ImageJ，Pymol，HE病理分析， 这些工具体系可以直接通过AI对话使用，你将无需再学习复杂的软件操作过程 。

我是没学过ImageJ的，但在OmicOS，你可以直接通过对话，例如输入“请帮我实现细胞计数并且可视化轮廓”，那么就会自动完成ImageJ的分析

AI对话ImageJ
