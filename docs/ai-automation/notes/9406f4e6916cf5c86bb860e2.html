Windows 下其实从来不缺终端工具。

系统自带有 Windows Terminal，远程连接可以用 Xshell，功能大而全的可以用 MobaXterm。它们当然都能用，而且很多人也用了很多年。

但问题是，我一直觉得 Windows 下始终缺少一个“真正顺手”的终端。

有些工具太复杂，像 Xshell 这一类软件，更像是传统的 SSH 连接管理器。它适合管理很多服务器、配置很多会话、做比较正式的远程运维，但它的设计思路还是偏传统：先建会话，再连服务器，再围绕连接做管理。

MobaXterm 也很强，集成了很多东西，SSH、SFTP、X server、远程文件管理都放在一起。但也正因为它什么都有，整个工具会变得很重，界面也更像一个远程运维套件。

而我想要的不是一个越来越复杂的“大工具箱”。

我想要的是一个真正适合日常开发的 Windows 终端：打开就能用，连接远程服务器也顺手，配合 WSL 也自然，最重要的是，它应该适合今天 Codex、Claude Code 这类 AI 编程工具的工作流。

这就是我做 Phantty 的原因。

开源免费：https://phantty.cc-remote.app/

Phantty 不是单纯为了替代 Windows Terminal，也不是为了做一个更复杂的 Xshell 或 MobaXterm。它更像是一个面向 AI 时代重新设计的 Windows 终端。

它关注的不是“我能不能连上服务器”，而是：

连上之后，我每天反复做的事情，能不能更简单？

功能一：Ctrl + Shift + Click 下载远程文件#

在远程服务器上工作时，经常会遇到一个场景：终端里出现了一个文件路径，我想把它下载到本地。

传统做法一般是复制路径，然后重新写一条 scp 命令。你需要确认远程地址、用户名、远程路径、本地保存位置。这个过程不难，但非常烦。

Phantty 里可以直接对远程文件路径使用 Ctrl + Shift + Click 。

比如终端里出现：

/home/user/project/results/report.html

你可以直接按住 Ctrl + Shift 点击这个路径，Phantty 就会把远程文件下载到本地。

也就是说，这里的设计不是 让你再去记一遍 scp 命令 ，而是 把远程文件下载变成一个点击动作 。

这对我来说非常重要。因为开发过程中真正浪费时间的，往往不是某个大功能，而是这些每天重复几十次的小摩擦。

功能二：拖动文件到终端，直接上传到远程服务器#

下载之外，另一个高频操作就是上传。

比如你本地有一个配置文件、脚本、图片、数据文件，想传到当前 SSH 会话所在的服务器目录。传统方式还是 scp ，或者打开 SFTP 工具，再手动找目录。

Phantty 里可以直接把本地文件拖进终端。

如果你当前在 SSH 远程环境里，Phantty 会把这个文件上传到远程服务器当前目录，并把上传后的路径返回到终端里。

整个过程就是：

本地文件 → 拖进终端 → 上传到远程当前目录 → 获得远程路径

这件事看起来很小，但用起来会非常自然。

我不想每次上传文件都切到另一个工具，也不想为了一个临时文件打开完整的文件传输界面。既然我已经在终端里工作，那么上传文件这件事，也应该直接发生在终端里。

功能三：直接粘贴图片到 Codex / Claude Code#

今年使用 Codex、Claude Code 这类 AI 编程工具的人越来越多，而这些工具很多时候就运行在终端里。

但这里有一个很烦的问题：如果我想把截图给 AI 看，该怎么办？

传统流程通常是：

截图 → 保存图片 → 上传到远程服务器 → 复制图片路径 → 粘贴给 AI

如果 AI 工具运行在本地还好，麻烦少一点；如果它运行在远程服务器里，这个流程就更绕。

Phantty 解决的是这个痛点：你可以直接把剪贴板里的图片粘贴到终端。

这意味着你可以截图之后，直接粘贴给终端里的 Codex 或 Claude Code。即使你的 AI 工具运行在远程服务器上，也可以更自然地获得图片上下文。

这对 AI 编程非常有用。因为很多问题不是几句话能说清楚的。

比如前端页面布局错了，浏览器里出现奇怪报错，图表显示不对，生信分析结果图需要判断，软件界面里有一个难以描述的状态，这些场景都很适合直接截图给 AI。

以前你要把这些信息讲给 AI，需要绕很多步。现在在 Phantty 里，可以更接近直觉：看到问题，截图，粘贴，继续让 AI 处理。

也就是说，这里的设计不是 把终端做成聊天软件 ，而是 让终端里的 AI 真正获得它需要的上下文 。

功能四：Ctrl + Click 预览 Markdown 文件#

开发过程中，我们经常会遇到各种 Markdown 文件：

README.md
CHANGELOG.md
notes.md
result.md
analysis.md

传统做法是用 cat 、 less 、 vim ，或者打开编辑器查看。能看，但不够顺手。

Phantty 支持对 Markdown 文件使用 Ctrl + Click 预览。

当终端输出里出现一个 Markdown 文件路径时，你可以直接点击打开预览，不需要离开当前终端环境。

这个功能特别适合看项目说明、分析记录、运行日志、课程文档和 AI 生成的报告。

很多时候，我们并不是想“编辑”这个 Markdown 文件，只是想快速确认里面写了什么。那最自然的方式就应该是：看到路径，点一下，直接预览。

功能五：更适合 WSL、SSH 和远程开发#

Phantty 不是只面向本地命令行的工具。

它面向的是今天真实的开发环境：Windows 本地、WSL、远程 Linux 服务器，以及运行在这些环境里的各种命令行工具。

很多终端在本地用起来还可以，但一到 SSH 或 WSL 场景，就会变得割裂。比如文件上传下载、图片传递、Markdown 预览，这些操作常常需要用户自己再去找别的工具补上。

Phantty 想把这些能力统一起来。

无论你是在本地工作，还是在 WSL 里开发，还是 SSH 到远程服务器上运行 Codex / Claude Code，Phantty 都希望这些操作尽量保持一致。

这也是它和传统 SSH 工具最大的区别。

Xshell、MobaXterm 这类工具解决的是“如何连接服务器”和“如何管理远程会话”。

而 Phantty 更关心的是“连接服务器之后，开发者每天在终端里做的事情，能不能更自然”。

功能六：让 AI 更适合待在终端里#

我一直觉得，AI 最适合待的地方其实是终端。

因为终端连接着真实的开发现场：代码、日志、进程、服务器、脚本、数据、环境变量、软件依赖、运行结果。

如果 AI 只是待在网页聊天框里，它离真实工作还有一段距离。你需要不断复制粘贴，把终端里的信息搬给它，再把它的建议搬回终端执行。

但如果 AI 本身就运行在终端里，这个距离会被大幅缩短。

Phantty 做的这些功能，本质上都是在减少这种距离：

远程文件路径可以直接下载
本地文件可以直接拖进远程终端
截图可以直接粘贴给 AI
Markdown 文件可以直接预览

这些功能不是为了炫技，而是为了让终端更适合今天的 AI 编程工作流。

结语#

Windows 下不是没有终端工具。

只是长期以来，我们要么使用系统自带的通用终端，要么使用 Xshell、MobaXterm 这类偏传统、偏复杂的远程工具。

它们都能解决问题，但我一直想要一个更轻、更直接、更适合日常开发和 AI 工作流的 Windows 终端。

Phantty 就是这个想法的产物。

它解决的都是一些非常具体的问题：

远程文件怎么快速下载？

本地文件怎么快速上传？

截图怎么直接给终端里的 AI？

Markdown 文件怎么不用离开终端就能预览？

这些问题每一个都不大，但每天重复出现，就会变成开发体验里的摩擦。

而 Phantty 想做的，就是把这些摩擦一个一个抹掉。

它不是为了让你多学一套复杂工具，而是为了让你少做很多无意义的操作。

终端应该更自然。

终端应该更适合 AI。

这就是我做 Phantty 的原因。
