English | 中文

随时随地，通过任何聊天应用控制您的本地 AI 代理。

cc-connect 将运行在您机器上的 AI 代理与您已使用的消息平台连接起来。
代码审查、研究、自动化、数据分析——人工智能代理能做的任何事情，
现在可以通过手机、平板电脑或任何装有聊天应用程序的设备访问。

🆕 最新动态（测试版）#

这些亮点功能目前仅存在于 测试版/预发布 版本中——请安装 cc-connect@beta 或获取 预发布 二进制文件。它们 尚未 包含在默认的 稳定 版本中；在正式发布之前，相关细节可能会有所更改。

  • 个人微信 — 通过 ilink 长轮询技术，使用 微信（个人版） 与您的本地代理聊天；二维码 weixin setup ，CDN 媒体，无公网 IP。 设置 → docs/weixin.md
  • 自动压缩 — 当会话估计超过您的阈值时，cc-connect 可以修剪上下文，以便长时间运行的线程能够继续工作，而不是默默地崩溃。
  • 更友好的 --continue — 继续时会创建子进程，这样你的桥接会话就不会意外地继承一个未完成的 CLI 终端会话。
  • 带有边界的 Cron — 每次都在 新的会话 中运行作业，并限制 每个作业的超时时间 ，以防止失控的任务阻塞机器人。
  • 更丰富的平台 ——例如 Discord 的 @everyone / @here 、 Telegram 的 语音回复、 Feishu 对回复线程和异步分发的修复。

✨ 为什么选择 cc-connect？#

🤖 通用代理支持#

7 款 AI 代理 ——Claude Code、Codex、Cursor Agent、Qoder CLI、Gemini CLI、OpenCode、iFlow CLI。您可以根据工作流程选择合适的代理，也可以同时使用全部代理。

📱 平台灵活性#

10 个聊天平台 ——飞书、钉钉、Slack、Telegram、Discord、企业微信、LINE、QQ、QQ Bot（官方版），以及用于 个人微信的 微信（个人 ilink） 。 个人微信 目前仅提供测试版/预发布版本 ——请安装 cc-connect@beta 或 GitHub 预发布 二进制文件；默认的 稳定 版 npm 包 尚未 包含 weixin 平台。大多数平台不需要 公网 IP 地址 。

🔄 多智能体编排#

多机器人接力 ——将多个机器人绑定到一个群聊中，让它们彼此交流。向 Claude 提问，从 Gemini 获取见解——所有这一切都可以在一次对话中完成。

🎮 完全聊天控制#

通过聊天进行完全控制 ——切换模型（ /model ）、调整推理（ /reasoning ）、更改权限模式（ /mode ）、管理会话，所有操作均可通过斜杠命令完成。

聊天中的目录切换 — 使用 /dir <path> 更改下一个会话的起始位置（兼容别名是 /cd <path> ），还可以通过 /dir <number> / /dir - 快速跳转到历史记录。

🧠 持久内存#

代理内存 — 无需接触终端即可读取和写入代理指令文件（ /memory ）。

⏰ 智能调度#

定时任务 ——用自然语言设置定时任务。 “每天早上 6 点，汇总 GitHub 热搜” 就能轻松实现。

🎤 多模态支持#

语音和图像 — 发送语音消息或屏幕截图；cc-connect 处理 STT/TTS 和多模式转发。

📦 多项目建筑#

多项目 ——一个流程，多个项目，每个项目都有自己的代理+平台组合。

🌍 多语言界面#

支持 5 种语言 ——原生支持英语、中文（简体和繁体）、日语和西班牙语。内置 i18n 功能，确保每位用户都能轻松上手。

左：Lark | Telegram | 右：微信

🚀 快速入门#

🤖 通过 AI 代理安装和配置（推荐）#

最简单的方法 ——将此文件发送给 Claude Code 或任何 AI 编码代理，它将为您处理整个安装和配置过程：

Follow https://raw.githubusercontent.com/chenhg5/cc-connect/refs/heads/main/INSTALL.md to install and configure cc-connect.

📦 手动安装#

通过 npm：

# Stable version
npm install -g cc-connect

# Beta version (more features, may be unstable)
npm install -g cc-connect@beta

个人微信（Weixin ilink）： 仅在 beta/预发布 版本中可用（ cc-connect@beta 或 Releases 下的预发布资源）。 稳定的 npm install -g cc-connect 在正式版发布前 不 包含此平台。

从 GitHub Releases 下载二进制文件：

# Linux amd64 - Stable
curl -L -o cc-connect https://github.com/chenhg5/cc-connect/releases/latest/download/cc-connect-linux-amd64
chmod +x cc-connect
sudo mv cc-connect /usr/local/bin/

# Beta version (from pre-release)
curl -L -o cc-connect https://github.com/chenhg5/cc-connect/releases/download/v1.x.x-beta/cc-connect-linux-amd64

从源代码构建（需要 Go 1.22+）：

git clone https://github.com/chenhg5/cc-connect.git
cd cc-connect
make build

⚙️ 配置#

mkdir -p ~/.cc-connect
cp config.example.toml ~/.cc-connect/config.toml
vim ~/.cc-connect/config.toml

在项目中设置 admin_from = "alice,bob" 以允许这些用户 ID 运行 /dir 和 /shell 等特权命令。当用户运行 /dir reset 时，cc-connect 会恢复配置的 work_dir 并清除存储在 data_dir/projects/<project>.state.json 下的持久化覆盖。

▶️ 运行#

./cc-connect

🔄 升级#

# npm
npm install -g cc-connect

# Binary self-update
cc-connect update           # Stable
cc-connect update --pre     # Beta (includes pre-releases)

🛡️操作系统用户隔离（以用户 run_as_user ）#

在 Linux/macOS 系统上，项目可以以不同的 Unix 用户身份运行其代理，从而实现操作系统级别的文件系统隔离，使其与运行 cc-connect 的管理用户保持隔离。目前 Claude Code 支持此功能。

<a href="projects">projects</a>
name = "claude-sandboxed"
run_as_user = "partseeker-coder"
run_as_env = ["PGSSLROOTCERT"]

目标用户需要从管理员处获得免密码 sudo 权限，自身不具备 sudo 权限，对 work_dir 拥有读写权限，并且需要拥有自己的 ~/.claude/settings.json 使用代理使用的任何凭据。如果您通过以下方式进行身份验证： claude.ai OAuth，创建指向目标用户 ~/.claude/.credentials.json 的符号链接 更新到主管的副本，以便令牌刷新保持同步——参见 环境传播检查清单 详情请见。 docs/usage.md 完整设置。

启动 cc-connect 之前，请使用以下命令审核设置：

cc-connect doctor user-isolation

该程序运行三个允许/禁止的预检门和一个隔离探测器，用于报告目标用户可以读取和不能读取的内容。如果任何一个预检门失败，或者探测器检测到跨用户泄漏，cc-connect 将拒绝启动。

📎 代理附件发送返回#

当客服人员生成本地屏幕截图、图表、PDF、文件包或其他文件时，可以将该附件发送回当前聊天。

首个版本支持：

  • Feishu
  • 电报

如果您的代理程序没有原生注入系统提示符，请在升级后在聊天窗口中运行以下命令：

/bind setup

或者：

/cron setup

这样可以刷新项目内存文件中的 cc-connect 指令，以便代理知道如何发送附件。

您可以在 config.toml 中全局控制此功能：

attachment_send = "on"  # default: "on"; set to "off" to block image/file send-back

此开关与代理的 /mode 无关。它仅控制 cc-connect send --image/--file 。

例如：

cc-connect send --image /absolute/path/to/chart.png
cc-connect send --file /absolute/path/to/report.pdf
cc-connect send --file /absolute/path/to/report.pdf --image /absolute/path/to/chart.png

笔记：

  • 绝对路径是最安全的选择。
  • --image 和 --file 都可以重复使用。
  • attachment_send = "off" 仅禁用附件发送功能；普通文本回复功能仍然有效。
  • 此命令用于生成附件，不适用于普通文本回复。
