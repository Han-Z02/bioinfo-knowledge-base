收件#

直接从外部链接入库#

发送外部平台链接，或使用 $hz-link-to-wiki <URL>。该 skill 通过 agent-reach 读取用户提供的页面，按内容选择知识库分类，写中文笔记与来源证据，分配 kb_id、更新导入日志并生成 HTML。学术论文使用 hz-paper-analysis；链接内容无法读取时，不生成推测性笔记。知识库写入不自动推送 GitHub，线上发布仍按发布流程执行。

在知识库根目录运行，先预览：

npm run kb:intake -- --file "D:\材料\paper.pdf" --library 2 --title "论文标题"

确认计划符合预期后，用同一命令加 --apply 建立草稿。编号 1–4 分别是口腔生信、文献精读、生信教程、AI 与自动化。

收件副本与草稿放入该库 00_inbox/<文件内容摘要>/，保留 SHA-256 回执。收件时自动分配永久编号，并写入草稿和回执；重复接收同一文件会返回已有收件记录和编号。原文件保持原位。草稿标记 publish: false，不进入网站及全文索引。

精读与正式归库#

论文按 hz-paper-analysis 整理研究问题、数据与样本层级、ROADMAP、逐图分析、证据链、Data Access 和复现路线。只有二手解读时，明确标注来源状态；计算推断与实验验证分开记录。

教程补充用途、输入、操作、输出、版本、代码来源与实际验证范围。将原文证据和可复用方法分开保留，同源链接不意味着应删除其中一份。

精读复核后，将笔记与附件一起放入所属库 01_sources 或 02_wiki，更新主题索引与 05_logs/ingest_log.md。如果适合进入加密阅读版，将草稿状态改为完成，并设置 publish: true。不要直接清除所有历史条目的私密标记。

手动新建笔记后运行 npm run kb:assign-ids -- --file "笔记相对路径.md" 预览，再加 --apply 分配编号。整理历史笔记时先用 npm run kb:assign-ids 预览批量编号，再运行 npm run kb:assign-ids -- --apply。

检查与阅读#

npm run kb:check
npm run kb:report

报告位于 04 AI_API与自动化库/05_logs/知识库工作流检查。检查覆盖待归库、来源、摘要、标签、日期、日志回链、同源候选和编号的缺失、格式与重复；不自动修改笔记，也不代表科研结论已经核实。

报告同时检查全库编号是否缺失、格式错误或重复。发布构建会拒绝缺编号和重复编号的公开笔记。编号显示在站点笔记卡片、文章页和搜索结果中，输入 KB-000123 可直接搜索。

正文更新后，生成单篇阅读版：

node tools/kb/render_note_html.mjs "笔记的相对路径.md" --force

全站预览：

npm run site:preview
npm run site:serve

本机打开 http://127.0.0.1:8765/。首页和文章工具栏可进入全库搜索，支持多个关键词同时匹配、正文片段、板块筛选、排序与网址还原；/ 聚焦搜索，Esc 清空关键词。

加密与发布#

npm run site:build:local
npm run site:verify
npm run site:serve:secure

本机打开 http://127.0.0.1:8766/，使用已有共享密码。构建会先验收明文，再加密并验收，全部通过后才替换输出。构建报告保存在本地 05_logs，不随阅读页面发布。

搜索索引只内嵌于加密的 search.html，没有明文检索数据接口。个人事务、待确认归档、收件箱、模板、日志和私密笔记不进入网站。原始 Zotero 数据库不参与静态站点发布。

确认需要上线后，维护者运行 npm run site:sync。这会提交并推送现有站点仓库；还需核对远端部署结果。当前共享密码提供统一解锁，不提供独立用户账号。

维护说明#

  • 工具与参数详见本地 tools/kb/README.md。
  • npm run kb:test 验证搜索、重复收件、检查与加密边界。
  • 缺失图片和未发布链接见本地 05_logs/site-build-report.json；应核对原材料后逐条修复。
  • 不要将 .preview-site 明文预览目录、检查报告或密码文件提交到公开仓库。
  • 流程与实现于 2026-10-24 更新；每次对外发布仍以当次验收为准。
