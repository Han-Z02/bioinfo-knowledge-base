论文检索 MCP#

这是一个基于模型上下文协议 (MCP) 的服务器，用于搜索和下载来自多个来源的学术论文。该项目遵循“免费优先”策略：优先使用开放和公共数据源，在可选 API 密钥能够提升稳定性或覆盖范围时予以支持，并保持特定数据源连接器的可扩展性，以满足高级用户的需求。

概述#

paper-search-mcp 是一个基于 Python 的工具，用于从各种平台搜索和下载学术论文。它提供论文搜索、PDF 下载和文本提取等功能，非常适合研究人员和 AI 驱动的工作流程。它可以作为 MCP 服务器（适用于 Claude Desktop 和其他 MCP 客户端）使用，也可以作为带有命令行界面的 Claude Code 技能使用。

项目原则#

  • 免费优先 ：公共和开源是默认的发展路线图。付费或受限资源并非本项目的核心方向。
  • 可选 API 密钥 ：仅当 API 密钥能够提升稳定性、限制速率或提高元数据质量时才予以支持。在条件允许的情况下，MCP 仍应尽可能在不使用 API 密钥的情况下正常运行。
  • LLM 友好型检索 ：搜索结果应标准化、去重，并尽可能完整，以适应下游 LLM 工作流程。
  • 来源透明度 ：不同的来源各有优势。MCP 应该明确指出这些权衡取舍，而不是假装每个来源都支持全文检索。

特征#

  • 双层架构 ：
    • 第 1 层（统一工具） ：高级 search_papers 用于多源并发搜索和去重， download_with_fallback 依赖于出版商开放获取链接，并提供顺序回退。
      • 第 2 层（平台连接器） ：针对特定学术平台（arXiv、PubMed、bioRxiv、Semantic Scholar 等）的模块化连接器，配备有通过正则表达式文本分析或 API 字段进行智能 DOI 提取的功能。
  • 多源支持 ：可从 arXiv、PubMed、bioRxiv、medRxiv、Google Scholar、IACR ePrint Archive、Semantic Scholar、Crossref、OpenAlex、PubMed Central (PMC)、CORE、Europe PMC、dblp、OpenAIRE、CiteSeerX、DOAJ、BASE、Zenodo、HAL、SSRN、Unpaywall（DOI 查找）以及可选的 Sci-Hub 工作流程中搜索和下载论文。
  • 标准化输出 ：论文通过 Paper 类以一致的字典格式返回。
  • 免费优先设计 ：开放和公共资源优先于任何可选的商业或受限集成。
  • 可选的 API 密钥增强功能 ：像 Semantic Scholar 这样的资源可以通过用户提供的 API 密钥更好地工作，但并不旨在强制付费使用。
  • 发现 + 检索工作流程 ：可以使用 Google Scholar 和 Crossref 进行发现和 DOI 回填，而开放存储库和出版商链接则用于在可用时进行合法的全文解析。
  • OA-First Fallback Chain: download_with_fallback 现在遵循源原生下载 → OpenAIRE/CORE/Europe PMC/PMC 发现 → Unpaywall DOI 解析 → 可选的 Sci-Hub。
  • MCP 集成 ：与 MCP 客户端兼容，用于 LLM 上下文增强。
  • 可扩展设计 ：通过扩展 academic_platforms 模块，轻松添加新的学术平台。

采购策略#

长远目标不是依赖单一搜索引擎，而是将多个免费公共资源结合起来，并明确它们各自的角色：

  • 开放元数据骨干网 ：Crossref、OpenAlex、Semantic Scholar、dblp、CiteSeerX、SSRN、Unpaywall（以 DOI 为中心的 OA 元数据）。
  • 学科特定来源 ：arXiv、PubMed、PubMed Central、Europe PMC、IACR。
  • 开放获取全文来源 ：arXiv、PMC、CORE、OpenAIRE、DOAJ、BASE、Zenodo、HAL、出版商开放获取链接。
  • 发现和 DOI 恢复 ：当其他公共元数据来源不完整时，Google Scholar 可用于查找标题、版本和 DOI 线索。

推荐的优先免费路线图：

  1. 保持现有公共资源的稳定。
  2. 添加 OpenAlex 作为广泛的免费元数据源。
  3. 添加 PubMed Central 和 Europe PMC，以增强生物医学全文访问能力。
  4. 添加 CORE 和 OpenAIRE，实现基于存储库的开放获取检索。
  5. 主要将 Google Scholar 用作发现资料的备用途径，而不是作为主要权威来源。

已知的上游限制#

部分搜索失败是由外部服务提供商不稳定造成的，并非本项目本身存在漏洞：

来源 症状 原因 变通方法
谷歌学术 返回 0 个结果/空 HTML 机器人检测（验证码） 将 PAPER_SEARCH_MCP_GOOGLE_SCHOLAR_PROXY_URL 设置为代理
语义学者 429 速率限制反应 匿名访问速率限制 设置 PAPER_SEARCH_MCP_SEMANTIC_SCHOLAR_API_KEY ；如果密钥被拒绝（403），连接器将自动重试，不使用密钥。
CORE 500 / 超时错误 未经认证的限速 设置 PAPER_SEARCH_MCP_CORE_API_KEY （免费）；连接器将使用指数退避算法重试，并在出现 401/403 错误时回退到无密钥模式。
OpenAIRE 瞬态 403 响应 基于 IP 的会话速率限制 连接器对每个配置文件重试 3 次，依次升级：普通会话 → XML Accept 标头 → 使用 Mozilla UA 的原始 requests.get
CiteSeerX 通过网页存档重定向到 404 页面 PSU 端点间歇性重定向到存档 没有变通办法；连接器会优雅地返回空值。
BASE 搜索结果为 0 OAI-PMH 终点需要机构 IP 注册 请登录 base-search.net 注册以获取 API 访问权限；否则，连接器将优雅地返回空值。
SSRN HTTP 403 机器人检测（Cloudflare） 没有变通办法；连接器会尝试两个端点，并在失败时返回清晰的消息。
PMC / 欧洲 PMC PDF 下载代理错误 本地代理阻止了直接的 HTTPS PDF 下载 禁用代理或改用 download_with_fallback
支付墙 完全跳过 UNPAYWALL_EMAIL 环境变量未设置 在 .env 中设置 PAPER_SEARCH_MCP_UNPAYWALL_EMAIL

可选付费平台连接器（第三阶段）#

IEEE Xplore 和 ACM 数字图书馆连接器以 可选框架的 形式提供。 默认情况下，它们处于禁用状态 ——除非您显式配置相应的密钥，否则不会进行任何 API 调用。

平台 环境是 地位
IEEE Xplore PAPER_SEARCH_MCP_IEEE_API_KEY 🚧 骨架 — 搜索已注册、下载/读取引发 NotImplementedError
ACM 数字图书馆 PAPER_SEARCH_MCP_ACM_API_KEY 🚧 骨架 — 搜索已注册、下载/读取引发 NotImplementedError

如何启用：

export PAPER_SEARCH_MCP_IEEE_API_KEY=<your_ieee_key>       # free key at https://developer.ieee.org/
export PAPER_SEARCH_MCP_ACM_API_KEY=<your_acm_key>         # see https://libraries.acm.org/digital-library

一旦设置了密钥，相应的源就会自动添加到 ALL_SOURCES 中，并且其 MCP 工具（ search_ieee / search_acm 、 download_ieee / download_acm 、 read_ieee_paper / read_acm_paper ）会在服务器启动时注册。

如果没有密钥，连接器只会记录启动警告——服务器的其余部分不受影响。

免费源代码扩展（第四阶段）#

MCP 服务器现在集成了三个额外的开源连接器：

  • zenodo ：官方 Zenodo REST API 连接器（搜索 + 记录相关的 PDF/读取支持）。
  • hal ：HAL 公共 API 连接器（搜索 + 记录相关的 PDF/读取支持）。
  • ssrn ：当有直接的公共 PDF 链接可用时，具有强化解析器和尽力下载/读取的发现优先连接器。
  • unpaywall ：以 DOI 为中心的 OA 元数据源，用于独立查找 ( search_unpaywall ) 和备用 URL 解析。

SSRN 集成始终以合规性为先：它仅尝试使用 SSRN 页面上公开的直接 PDF 链接。如果需要登录或受限访问，连接器会返回明确的错误信息，而不是绕过访问控制。

科学中心公告#

Sci-Hub 支持可以作为可选连接器继续供明确选择启用它的用户使用，但不应将其视为默认或推荐的全文路径。

  • 可用性不稳定，镜像经常变化。
  • 法律和政策风险因司法管辖区而异。
  • README 文件和工具说明应明确指出，用户有责任启用和使用该工具。
  • 应尽可能优先尝试开放获取和出版商允许的资源。

安装#

选择最适合您工作流程的方法。所有方法都支持相同的 可选 API 密钥 。

克劳德代码（技能）——推荐给克劳德代码用户#

安装方式为 Claude Code 技能，而非 MCP 服务器。这样，当您提及查找论文、学术文献等时，Claude 即可自动访问论文搜索功能——无需进行 MCP 配置。

先决条件 ： uv 和 Claude Code 。

第一步——克隆仓库：

git clone https://github.com/openags/paper-search-mcp.git ~/paper-search-mcp

步骤 2 — 安装技能：

mkdir -p ~/.claude/skills/paper-search
cp ~/paper-search-mcp/claude-code/SKILL.md ~/.claude/skills/paper-search/SKILL.md

步骤 3 — 更新技能中的存储库路径：

编辑 ~/.claude/skills/paper-search/SKILL.md 并将每个 <REPO_PATH> 替换为克隆的绝对路径（例如 /Users/yourname/paper-search-mcp ）。

步骤 4（可选）— 配置 API 密钥：

在仓库根目录下创建一个 .env 文件，用于存放可选的 API 密钥（请参阅 环境变量 ）。

就是这样。 下次启动克劳德代码时，只需让它查找文件——该技能会自动激活。例如：

  • 请帮我查找关于 CRISPR 基因编辑的最新论文。
  • “在 arXiv 和语义学者中搜索 Transformer 注意力机制”
  • “下载 arXiv 论文 2106.12345 的 PDF 文件”

该技能使用 CLI（ paper-search ），它封装了与 MCP 服务器相同的库，输出 JSON 用于搜索/下载，输出纯文本用于读取。

MCP 服务器配置文件位置 （适用于以下方法）

  • macOS ： ~/Library/Application Support/Claude/claude_desktop_config.json
  • Windows ： %APPDATA%\Claude\claude_desktop_config.json
  • Linux ： ~/.config/Claude/claude_desktop_config.json

方法一 — Smithery（单命令，推荐用于 Claude Desktop）#

npx -y @smithery/cli install @openags/paper-search-mcp --client claude

Smithery 会自动为您写入正确的配置块，无需手动编辑 JSON。

方法二 uvx （无需安装，始终为最新版本）#

uvx 直接从 PyPI 运行软件包，无需永久安装。需要 uv 。

# Install uv (skip if already installed)
curl -LsSf https://astral.sh/uv/install.sh | sh

        "PAPER_SEARCH_MCP_CORE_API_KEY": "",
        "PAPER_SEARCH_MCP_SEMANTIC_SCHOLAR_API_KEY": "",
        "PAPER_SEARCH_MCP_ZENODO_ACCESS_TOKEN": "",

        "PAPER_SEARCH_MCP_IEEE_API_KEY": "",
        "PAPER_SEARCH_MCP_ACM_API_KEY": ""
      }
    }
  }
}

Environment Variables (.env file)#

Instead of putting keys directly in the JSON config you can store them in a .env file in the project root (auto-loaded on startup):

cp .env.example .env   # if running from source
# or create ~/.paper-search-mcp.env for global use

PAPER_SEARCH_MCP_UNPAYWALL_EMAIL=your@email.com
PAPER_SEARCH_MCP_CORE_API_KEY=
PAPER_SEARCH_MCP_SEMANTIC_SCHOLAR_API_KEY=
PAPER_SEARCH_MCP_ZENODO_ACCESS_TOKEN=
PAPER_SEARCH_MCP_GOOGLE_SCHOLAR_PROXY_URL=
PAPER_SEARCH_MCP_IEEE_API_KEY=
PAPER_SEARCH_MCP_ACM_API_KEY=

To use a custom path: export PAPER_SEARCH_MCP_ENV_FILE=/absolute/path/to/.env

Legacy variable names without the PAPER_SEARCH_MCP_ prefix (e.g. CORE_API_KEY, UNPAYWALL_EMAIL) are still supported for backward compatibility.
